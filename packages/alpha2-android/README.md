# alpha2 for Android (preview)

The alpha2 media engine as an Android library: export a timeline project to a video file, render stills, and play a preview into a `Surface`, with MediaCodec for decoding and encoding and Vulkan (or the CPU renderer) for drawing. The API is the `alpha2-mobile` Rust crate's, as Kotlin bindings generated by uniffi in the package `sh.alpha2`, plus the `Alpha2Android` object for what the bindings cannot express.

Mobile is a preview in this release. No Android library is published with alpha2 0.6.0: there is no Maven artifact and no release asset, so an app builds the AAR from a checkout. Its API, result shapes and error codes may change in any release. The [Swift package](../alpha2-swift/README.md) is the same API for iOS.

## Build the library

`scripts/build-android.sh`, run from the repository root, builds `packages/alpha2-android/lib/build/outputs/aar/lib-release.aar`: the Rust library for `arm64-v8a` and `x86_64` with 16 KB pages, stripped, and its Kotlin bindings generated from that library. It needs the Android NDK (`ANDROID_NDK_HOME`), `cargo-ndk`, Gradle 8.11 or later on `PATH`, the Android SDK (`ANDROID_HOME`) and the Rust targets `aarch64-linux-android` and `x86_64-linux-android`. `PROFILE=debug` builds unoptimized libraries, and `ALPHA2_ANDROID_ABIS` limits the ABIs (`ALPHA2_ANDROID_ABIS=x86_64` for an emulator). The unstripped libraries, for symbolicating crashes, stay in `lib/build/native/`. [Development](../../docs/development.md#mobile-targets) has the toolchain setup and how the library's own tests run.

An app that takes the AAR file adds its two dependencies itself:

```kotlin
dependencies {
    implementation(files("libs/alpha2.aar"))
    implementation("net.java.dev.jna:jna:5.17.0@aar")
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.10.2")
}
```

- Android 10 (API 29) or later, on 64-bit ARM or x86_64.
- The AAR carries R8 rules that keep what JNA and the bindings reach by name (`com.sun.jna`, the classes that implement or extend JNA types, and `sh.alpha2`), so a minified release build works without rules of its own.
- The native libraries are linked for 16 KB pages.
- The AAR carries `LICENSE.md`, `THIRD_PARTY_NOTICES.md` and, when the build named them with `ALPHA2_NOTICES`, the Rust crates' licences, under `META-INF/alpha2/`.
- Compose is built in; extractor plugins (`Plugin`) are not, since the build script does not enable the crate's `plugins` feature.

## Start

Call `Alpha2Android.init(context)` once, with any context of the app, before any other call: audio output and the codec list need it. `Application.onCreate` is the usual place.

```kotlin
import sh.alpha2.*

class App : Application() {
    override fun onCreate() {
        super.onCreate()
        Alpha2Android.init(this)
    }
}
```

An `Alpha2` is a session: its renderer and decode settings, its fonts and its pause state. It is `AutoCloseable`; keep one for the app's lifetime or close it with `use`.

```kotlin
val engine = Alpha2(EngineConfig(RendererMode.AUTO, VideoDecodeMode.AUTO, VideoFrameMode.AUTO))
```

- `RendererMode`: `AUTO` draws on the GPU and on the CPU renderer when no GPU device opens, `GPU` fails with `GpuInitFailed` instead, `CPU` never opens a GPU device. It applies to exports and stills; a `Player` always draws on a GPU device that presents to its window.
- `VideoDecodeMode`: `AUTO` uses the hardware decoder and falls back to the software one once per source; `HARDWARE` and `SOFTWARE` use only one kind.
- `VideoFrameMode`: `AUTO` keeps hardware-decoded frames on the GPU when the device imports them, `CPU` always copies them into memory.
- `engine.setFonts(listOf(FontFile(bytes, 0u)))` sets the fonts text may use, in fallback order, and returns each one's family names. A project with text needs them before it renders.

## Export

```kotlin
val request = ExportRequest(
    projectJson = projectJson,
    assets = mapOf("image-1" to File(filesDir, "image.png").absolutePath),
    frames = emptyMap(),
    resources = emptyMap(),
    outputPath = File(cacheDir, "export.mp4").absolutePath,
    overwrite = true,
    container = null, // from the output's extension: mp4, mov, mkv or webm
    videoCodec = null, // the container's default
    audioCodec = null,
    includeAudio = true,
    startTicks = null, // 0
    endTicks = null, // where the timeline ends
)
val progress = object : ExportProgress {
    override fun onProgress(event: ExportProgressEvent) {
        Log.i("export", "${event.framesDone} of ${event.framesTotal}")
    }
}
// In a coroutine:
val outcome = engine.export(request, progress).use { handle -> handle.outcome() }
val report = JSONObject(outcome.reportJson)
```

- Paths are files inside the app's sandbox. `assets` maps each source id to its file (and effect resources by resource id), `frames` an image sequence's frame files by source id, and `resources` the files an SVG or Lottie source names outside itself, by source id and locator.
- The output is written beside its path and moved into place when it is complete; the app moves or shares it from there. An existing file is refused unless `overwrite` is true.
- `export` checks the project and the request and returns an `ExportHandle` at once; the export runs on a library thread. `outcome()` suspends until it ends and can be awaited once; a second call fails with `InvalidInput`. `handle.cancel()` stops it, leaves no file behind, and `outcome()` then throws `Alpha2Exception.Aborted`. `isFinished()` and `isHeld()` (held by `pause`) report its state.
- `onProgress` runs on a library thread: keep it short. If it throws, the export stops with nothing written and `outcome()` throws `Failed` with code `PROGRESS_CALLBACK_FAILED`.
- When the hardware video encoder fails, the export runs once more on the software encoder; the report's `softwareRetry` says so.
- Mobile export does not take what the desktop host's `export` takes beyond these fields: no video or audio quality or bitrate, no output frame rate (the project's is used), no alpha, no 10-bit output, no loudness normalization and no runtime WGSL effects.

## Stills, conform and capabilities

- `engine.stills(StillsRequest(...))` renders frames to 8-bit sRGB RGBA PNG files, as an export draws them before encoding. Each `StillEntry(timeTicks, outputPath)` renders the frame of the project's grid that holds the time; `alpha` keeps the project's transparency. It runs on the calling thread and blocks there while the session is paused, so call it off the main thread.
- `engine.conform(ConformRequest(projectJson, assets, purpose))` reports whether each source's file opens: its container is read and a decoder takes it. It does not compare the media with what the project recorded, and `purpose` is not read.
- `engine.capabilities()` reports the device: the renderer and GPU, the extension formats and what the encoders take.
- `validateProject(projectJson)` lists why a project is invalid, one line per problem, and `alpha2Version()` is the library's version.

Results are JSON strings in the library's own shapes, which are not the desktop host's protocol objects:

| Call | Fields |
| --- | --- |
| `capabilities()` | `hostVersion`, `os`, `osVersion`, `arch`, `renderer` (`gpu` or `cpu`), `gpu` (`adapter`, `backend`, `driver`, `softwareRasterizer`, or `unavailable` with the reason, or `null` under `RendererMode.CPU`), `features` (`extensions.svg`, `extensions.animated-image`, `extensions.lottie`, `extensions.exr`, `extensions.pdf`, `extensions.image-sequence`, `extensions.latex`, each `{available}`), `media` (`platform`: `android`, `containers`, `videoEncoders`, `audioEncoders`) |
| `conform()` | `sources`: `{id, path, readable, reason}` each |
| `outcome().reportJson` | `container`, `videoCodec`, `videoEncoder`, `hardwareEncoder`, `softwareRetry`, `audioCodec`, `audioEncoder`, `audioBitrate`, `renderer`, `gpuUnavailable` (why no GPU drew, when one was allowed), `surfaceFrames` (frames that stayed on the GPU), `decodeDiagnostics`, `frames`, `width`, `height` |
| `stills()` | `stills`: `{output, frameTime, width, height}` each, `renderer`, `gpuUnavailable` |

## Preview

A `Player` plays a project into a window at the project's rate, with its sound, on a library thread of its own. Every call returns at once.

```kotlin
val player = Player(engine, PlayerRequest(projectJson, assets, emptyMap(), emptyMap()))
// In SurfaceHolder.Callback:
override fun surfaceChanged(holder: SurfaceHolder, format: Int, width: Int, height: Int) {
    Alpha2Android.attach(player, holder.surface, width.toUInt(), height.toUInt())
}
override fun surfaceDestroyed(holder: SurfaceHolder) = player.detachWindow()

player.play()
player.seek(60_000) // ticks: 120,000 a second
player.pause()
player.close() // or end(): stops the thread
```

- `Alpha2Android.attach` replaces any window attached before; call `detachWindow()` before the surface is destroyed, and `resize(width, height)` when it changes size.
- `positionTicks()`, `isPlaying()`, `isSounding()`, `framesPresented()`, `framesDropped()` and `lastError()` report what it did.

## Other calls

- Compose: `composeRequirements(specJson)`, `composeCompile(specJson, factsJson, fonts)`, `composeBind(documentJson, dataJson, optionsJson)`, `composeDataSchema(templateJson)`, `composeLint(templateJson, dataJson, optionsJson)` and `composeTemplates()`, the same functions as `alpha2/compose` in the browser. A compiled spec's `loudness` is `null` or `{target_lufs, true_peak_ceiling_dbtp}`.
- `applyEdit(projectJson, requestJson)` applies an edit operation (`remove_ranges`, `split_at`, `bake`) and returns `EditedProject(projectJson, reportJson)`; see the [host protocol](../../docs/host-protocol.md#edit) for the request.
- `engine.extract(request, extractor)` runs an `Extractor` the app implements over a source or the timeline and returns an `ExtractionHandle` (`cancel()`, `outcome()` with the data sets as JSON).
- `setDiagnosticListener(listener)` hands the app the library's diagnostic lines: GPU device errors, why an export draws on the CPU, a preview's failures, and every panic with its location. A listener runs on whichever library thread wrote the line. Without one, the lines go to the system log under the tag `alpha2`.

## App lifecycle

- `engine.pause()` holds exports, stills, extractions and previews before their next GPU work (a playing preview goes silent and keeps its position), and `engine.resume()` lets them continue.
- `engine.memoryWarning()` halves the decoded frames running work keeps; call it from `onTrimMemory` at `TRIM_MEMORY_RUNNING_LOW` and above. Work sizes its budget from the memory free when it starts.
- An export that should go on in the background runs in a foreground service of type `dataSync` (API 29 and later) or `mediaProcessing` (API 35 and later). An app targeting API 31 or later cannot start such a service from the background, so it starts the service and the export while visible. Without a service, the app pauses the session when it leaves the foreground and resumes it when it returns.

## Errors

Every failing call throws an `Alpha2Exception`, one subclass per kind:

| Subclass | Code | Fields |
| --- | --- | --- |
| `InvalidInput` | `INVALID_INPUT` | `problems`, one line each: an invalid project or request, or an outcome awaited twice |
| `EditRefused` | `INVALID_INPUT` | `refusal` (`unknown_data`, `empty_target`, `in_transition` and the others the host protocol lists), `reason` |
| `Unsupported` | `UNSUPPORTED` | `reason`: what this device or build cannot do |
| `EncodersRefused` | `ENCODERS_REFUSED` | `reason`, `refusals`: each encoder tried (`encoder`, `hardwareAccelerated`, `kind`: `absent`, `busy`, `unsuitable` or `unknown`, `reason`) |
| `GpuInitFailed` | `GPU_INIT_FAILED` | `reason`, under `RendererMode.GPU` |
| `OutputPublishFailed` | `OUTPUT_PUBLISH_FAILED` | `reason`, `keptPath`: the finished file kept beside the output, which the app then owns |
| `Aborted` | `ABORTED` | cancelled |
| `Failed` | `code` | `code`, `reason` |

`ConformFailed` (`CONFORM_FAILED`, with `reason` and `reportJson`) is part of the type, but no call of this release throws it: a source with no file in `assets` fails with `MISSING_INPUT`, and a file that does not open or decode with `SOURCE_FAILED` or `DECODE_FAILED`.

`Failed` carries the other codes: `DECODE_FAILED`, `ENCODE_FAILED`, `RENDER_FAILED`, `AUDIO_RENDER_FAILED`, `SOURCE_FAILED` (a source that could not be read during the export), `MISSING_INPUT`, `OUTPUT_IN_USE`, `OUTPUT_IO_FAILED`, `RESOURCE_LIMIT` (including a library thread that could not start), `PROGRESS_CALLBACK_FAILED`, `INTERNAL` (a library thread panicked: a defect), and for extractions `EXTRACTOR_FAILED`, `INVALID_EMIT` and the extractor's own codes.
