# alpha2 for Swift (preview)

The alpha2 media engine as a Swift package for iOS apps: export a timeline project to a video file, render stills, and play a preview into a `CAMetalLayer`, with VideoToolbox and AudioToolbox for decoding and encoding and Metal (or the CPU renderer) for drawing. The API is the `alpha2-mobile` Rust crate's, as Swift bindings generated by uniffi in the module `Alpha2`, over a static XCFramework (`Alpha2FFI`).

Mobile is a preview in this release. No Swift package is published with alpha2 0.6.0: there is no package registry entry and no release asset, so an app builds the package from a checkout. Its API, result shapes and error codes may change in any release. The [Android library](../alpha2-android/README.md) is the same API for Android.

## Build the package

On a Mac with Xcode, `scripts/build-ios.sh`, run from the repository root, builds this directory into a package an app can depend on: the Rust library as static libraries for iOS devices and the arm64 simulator in `Alpha2FFI.xcframework`, each slice with the privacy manifest (`PrivacyInfo.xcprivacy`), and the Swift bindings in `Sources/Alpha2`. It needs the Rust targets `aarch64-apple-ios` and `aarch64-apple-ios-sim` and the `llvm-tools` component: the script refuses a library that calls a required-reason API the privacy manifest does not declare. `PROFILE=debug` builds unoptimized libraries. [Development](../../docs/development.md#mobile-targets) has the toolchain setup and how the package's tests run.

Then add the directory to the app as a local package (in Xcode, Add Package Dependencies, then Add Local), or from another package:

```swift
dependencies: [.package(path: "../alpha2/packages/alpha2-swift")],
```

- iOS 17 or later. The simulator slice is arm64 only.
- Each framework slice carries `LICENSE.md`, `THIRD_PARTY_NOTICES.md` and, when the build named them with `ALPHA2_NOTICES`, the Rust crates' licences.
- Compose is built in; extractor plugins (`Plugin`) are not, since the build script does not enable the crate's `plugins` feature.

## Start

An `Alpha2` is a session: its renderer and decode settings, its fonts and its pause state. Keep one for the app's lifetime.

```swift
import Alpha2

let engine = Alpha2(config: EngineConfig(renderer: .auto, videoDecode: .auto, videoFrames: .auto))
```

- `RendererMode`: `.auto` draws on the GPU and on the CPU renderer when no GPU device opens, `.gpu` fails with `GpuInitFailed` instead, `.cpu` never opens a GPU device. It applies to exports and stills; a `Player` always draws on a GPU device that presents to its layer.
- `VideoDecodeMode`: `.auto` uses the hardware decoder and falls back to the software one once per source; `.hardware` and `.software` use only one kind.
- `VideoFrameMode`: on iOS, decoded frames are copied through memory in this release whatever the mode.
- `try engine.setFonts(fonts: [FontFile(bytes: fontData, faceIndex: 0)])` sets the fonts text may use, in fallback order, and returns each one's family names. A project with text needs them before it renders.

## Export

```swift
final class Progress: ExportProgress {
    func onProgress(event: ExportProgressEvent) throws {
        print("\(event.framesDone) of \(event.framesTotal)")
    }
}

let output = FileManager.default.temporaryDirectory.appendingPathComponent("export.mp4").path
let handle = try engine.export(request: ExportRequest(
    projectJson: projectJson,
    assets: ["image-1": imageURL.path],
    frames: [:], resources: [:], outputPath: output, overwrite: true,
    container: nil, // from the output's extension: mp4, mov, mkv or webm
    videoCodec: nil, audioCodec: nil, // the container's defaults
    includeAudio: true,
    startTicks: nil, endTicks: nil // 0 to where the timeline ends
), progress: Progress())
let outcome = try await handle.outcome()
let report = try JSONSerialization.jsonObject(with: Data(outcome.reportJson.utf8))
```

- Paths are files inside the app's sandbox. `assets` maps each source id to its file (and effect resources by resource id), `frames` an image sequence's frame files by source id, and `resources` the files an SVG or Lottie source names outside itself, by source id and locator.
- The output is written beside its path and moved into place when it is complete; the app moves or shares it from there. An existing file is refused unless `overwrite` is true.
- `export` checks the project and the request and returns an `ExportHandle` at once; the export runs on a library thread. `outcome()` waits until it ends and can be awaited once; a second call throws `InvalidInput`. `handle.cancel()` stops it, leaves no file behind, and `outcome()` then throws `Alpha2Error.Aborted`. `isFinished()` and `isHeld()` (held by `pause`) report its state.
- `onProgress` runs on a library thread: keep it short. If it throws, the export stops with nothing written and `outcome()` throws `Failed` with code `PROGRESS_CALLBACK_FAILED`.
- When the hardware video encoder fails, the export runs once more on the software encoder; the report's `softwareRetry` says so.
- Mobile export does not take what the desktop host's `export` takes beyond these fields: no video or audio quality or bitrate, no output frame rate (the project's is used), no alpha, no 10-bit output, no loudness normalization and no runtime WGSL effects.

## Stills, conform and capabilities

- `try engine.stills(request: StillsRequest(...))` renders frames to 8-bit sRGB RGBA PNG files, as an export draws them before encoding. Each `StillEntry(timeTicks:outputPath:)` renders the frame of the project's grid that holds the time; `alpha` keeps the project's transparency. It runs on the calling thread and blocks there while the session is paused, so call it off the main thread.
- `try engine.conform(request: ConformRequest(...))` reports whether each source's file opens: its container is read and a decoder takes it. It does not compare the media with what the project recorded, and `purpose` is not read.
- `engine.capabilities()` reports the device: the renderer and GPU, the extension formats and what the encoders take.
- `validateProject(projectJson:)` lists why a project is invalid, one line per problem, and `alpha2Version()` is the library's version.

Results are JSON strings in the library's own shapes, which are not the desktop host's protocol objects:

| Call | Fields |
| --- | --- |
| `capabilities()` | `hostVersion`, `os`, `osVersion`, `arch`, `renderer` (`gpu` or `cpu`), `gpu` (`adapter`, `backend`, `driver`, `softwareRasterizer`, or `unavailable` with the reason, or `null` under `.cpu`), `features` (`extensions.svg`, `extensions.animated-image`, `extensions.lottie`, `extensions.exr`, `extensions.pdf`, `extensions.image-sequence`, `extensions.latex`, each `{available}`), `media` (`platform`: `ios`, `containers`, `videoEncoders`, `audioEncoders`) |
| `conform()` | `sources`: `{id, path, readable, reason}` each |
| `outcome().reportJson` | `container`, `videoCodec`, `videoEncoder`, `hardwareEncoder`, `softwareRetry`, `audioCodec`, `audioEncoder`, `audioBitrate`, `renderer`, `gpuUnavailable` (why no GPU drew, when one was allowed), `surfaceFrames` (0 on iOS), `decodeDiagnostics`, `frames`, `width`, `height` |
| `stills()` | `stills`: `{output, frameTime, width, height}` each, `renderer`, `gpuUnavailable` |

## Preview

A `Player` plays a project into a `CAMetalLayer` at the project's rate, with its sound, on a library thread of its own. Every call returns at once.

```swift
let player = try Player(engine: engine, request: PlayerRequest(
    projectJson: projectJson, assets: assets, frames: [:], resources: [:]
))
try player.attach(layer: metalLayer, width: 1280, height: 720)
player.play()
player.seek(ticks: 60_000) // ticks: 120,000 a second
player.pause()
player.detachWindow()
player.end() // or release the player
```

- `attach(layer:width:height:)` replaces any layer attached before and keeps its own reference to it until it is detached or replaced; `resize(width:height:)` follows a size change.
- `positionTicks()`, `isPlaying()`, `isSounding()`, `framesPresented()`, `framesDropped()` and `lastError()` report what it did.

## Other calls

- Compose: `composeRequirements(specJson:)`, `composeCompile(specJson:factsJson:fonts:)`, `composeBind(documentJson:dataJson:optionsJson:)`, `composeDataSchema(templateJson:)`, `composeLint(templateJson:dataJson:optionsJson:)` and `composeTemplates()`, the same functions as `alpha2/compose` in the browser. A compiled spec's `loudness` is `null` or `{target_lufs, true_peak_ceiling_dbtp}`.
- `applyEdit(projectJson:requestJson:)` applies an edit operation (`remove_ranges`, `split_at`, `bake`) and returns `EditedProject` (`projectJson`, `reportJson`); see the [host protocol](../../docs/host-protocol.md#edit) for the request.
- `engine.extract(request:extractor:)` runs an `Extractor` the app implements over a source or the timeline and returns an `ExtractionHandle` (`cancel()`, `outcome()` with the data sets as JSON).
- `setDiagnosticListener(listener:)` hands the app the library's diagnostic lines: GPU device errors, why an export draws on the CPU, a preview's failures, and every panic with its location. A listener runs on whichever library thread wrote the line. Without one, the lines go to standard error.

## App lifecycle

- `engine.pause()` holds exports, stills, extractions and previews before their next GPU work (a playing preview goes silent and keeps its position), and `engine.resume()` lets them continue. iOS runs no GPU work in the background, so an app pauses when it leaves the foreground and resumes when it returns.
- `engine.memoryWarning()` halves the decoded frames running work keeps; call it from `didReceiveMemoryWarning`. Work sizes its budget from the memory free when it starts.

## Errors

Every failing call throws an `Alpha2Error`, one case per kind:

| Case | Code | Values |
| --- | --- | --- |
| `InvalidInput` | `INVALID_INPUT` | `problems`, one line each: an invalid project or request, or an outcome awaited twice |
| `EditRefused` | `INVALID_INPUT` | `refusal` (`unknown_data`, `empty_target`, `in_transition` and the others the host protocol lists), `reason` |
| `Unsupported` | `UNSUPPORTED` | `reason`: what this device or build cannot do |
| `EncodersRefused` | `ENCODERS_REFUSED` | `reason`, `refusals`: each encoder tried (`encoder`, `hardwareAccelerated`, `kind`: `absent`, `busy`, `unsuitable` or `unknown`, `reason`) |
| `GpuInitFailed` | `GPU_INIT_FAILED` | `reason`, under `.gpu` |
| `OutputPublishFailed` | `OUTPUT_PUBLISH_FAILED` | `reason`, `keptPath`: the finished file kept beside the output, which the app then owns |
| `Aborted` | `ABORTED` | cancelled |
| `Failed` | `code` | `code`, `reason` |

`ConformFailed` (`CONFORM_FAILED`, with `reason` and `reportJson`) is part of the type, but no call of this release throws it: a source with no file in `assets` fails with `MISSING_INPUT`, and a file that does not open or decode with `SOURCE_FAILED` or `DECODE_FAILED`.

`Failed` carries the other codes: `DECODE_FAILED`, `ENCODE_FAILED`, `RENDER_FAILED`, `AUDIO_RENDER_FAILED`, `SOURCE_FAILED` (a source that could not be read during the export), `MISSING_INPUT`, `OUTPUT_IN_USE`, `OUTPUT_IO_FAILED`, `RESOURCE_LIMIT` (including a library thread that could not start), `PROGRESS_CALLBACK_FAILED`, `INTERNAL` (a library thread panicked: a defect), and for extractions `EXTRACTOR_FAILED`, `INVALID_EMIT` and the extractor's own codes.

```swift
do {
    _ = try await handle.outcome()
} catch Alpha2Error.Failed(let code, let reason) {
    print("\(code): \(reason)")
}
```
