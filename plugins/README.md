# Plugins

Plugins an alpha2 host loads at run time, and the SDK to write them. This is a cargo workspace of its own, with its own lock; nothing in it is published or released from the repository, and no release archive or package contains a plugin.

- `sdk`: `alpha2-plugin-sdk`. Implement `Extractor` and call `export_extractor!` once; the crate builds as a core wasm module for `wasm32-unknown-unknown` and as a C-ABI library (`crate-type = ["cdylib"]`) for every other target. `include/alpha2_plugin.h` is the same ABI for plugins written in C, C++, Zig or Go. [`docs/plugin-abi.md`](../docs/plugin-abi.md) specifies it.
- `pack`: builds a plugin and writes a directory ready to upload to any server: the artifacts, the resources and `manifest.json` with relative URLs, SHA-256 hashes and sizes. It builds wasm with SIMD but without relaxed SIMD, and with getrandom's `unsupported` backend (a plugin has no randomness), and refuses a module that uses relaxed SIMD, threads or shared memory, or imports anything but the `alpha2` host functions.
- `first-party/`: the plugins meant to be published, one crate each.
  - `beats`: `alpha2.beats`, beats at one steady tempo and note onsets, each an instant with a `score`, and an `envelope` of onset strength and loudness normalized to 0..1, from the log spectral flux of 22050 Hz mono audio with an autocorrelation tempo estimate and dynamic-programming beat tracking. Its tests build click tracks, notes and silence with known answers.
  - `scenes`: `alpha2.scenes`, the cuts between shots as instants and the stretches of black, each with a `score`, from 4x4 grids of luma histograms compared by earth mover's distance. Its tests build frame sequences with cuts, fades, dissolves, flashes, noise and black at known frames.
  - `silence`: `alpha2.silence`, the intervals without speech, from Silero VAD (`model/` says where the model comes from) run through tract, with a `score` each. Its tests use a LibriVox recording with silences inserted at known places.
  - `track`: `alpha2.track`, a box picked on one frame followed through video by Lucas-Kanade corners and a RANSAC similarity aligned to the picked box, with its centre and motion per frame and lost marks where it no longer matches. Its tests track synthetic textured patches.
  - `transcribe`: `alpha2.transcribe`, the words spoken and their times, from a whisper.cpp ggml model the caller supplies in the `model` slot (`ggml-*.bin`, nothing pinned), native only. On x86-64 it needs a CPU with SSE4.2, AVX, AVX2, BMI2, FMA and F16C, which ggml is built with, and fails `begin` naming those the CPU lacks. Its model tests run when `ALPHA2_TEST_WHISPER_MODEL` names `ggml-tiny.en.bin` (and `ALPHA2_TEST_WHISPER_MODEL_MULTILINGUAL` names `ggml-tiny.bin`).
- `fixtures/`: plugins for tests only, never published.
  - `digest`, `scripted`: the engine's `alpha2.test.digest` and `alpha2.test.scripted` extractors as plugins, for loader and surface tests; `scripted` also has native-only faults (a crash, a hang, text on standard output, a process of its own) for the worker process tests.
  - `supplied`: `alpha2.test.supplied`, with a required file slot and an optional directory slot, which reports what it read, for the resource slot tests.

```sh
cargo run --manifest-path plugins/Cargo.toml -p alpha2-plugin-pack -- \
  plugins/fixtures/digest --out out/digest --target x86_64-unknown-linux-gnu
```

`scripts/pack-plugins.sh <directory>` packs every crate under `first-party/` (`--fixtures` adds `fixtures/`) into `<directory>/<group>/<name>`. A plugin crate keeps its descriptor in `descriptor.json` at its root (the SDK's `Extractor::DESCRIPTOR` includes it), files it reads through `resource()` under `resources/`, and entries `resources.json` lists, written to the manifest as they are: resources hosted elsewhere (`name`, `url`, `sha256`, `bytes`) and slots the caller fills (`name`, `supplied`). An `about.json` beside them is written as the manifest's `about`, the name and summary an interface shows. `--target` adds a native artifact for that triple (the host's when none is given; `--no-native` builds wasm only); building for another platform needs its linker. Native artifacts are built with `GGML_NATIVE=OFF` and `GGML_CCACHE=OFF`, so a crate that builds ggml targets a portable instruction set and no compiler cache, whatever directory pack runs from. A crate that cannot run as wasm, such as one that links a C or C++ runtime, sets `wasm = false` under `[package.metadata.alpha2-plugin]` in its `Cargo.toml`: pack builds no wasm for it, its manifest lists native artifacts only, and `--no-native` is refused (`scripts/pack-plugins.sh` leaves it out when given `--no-native`). Beside the manifest, pack writes the crate's `LICENSE*` and `NOTICE*` files (and those of its `model/` directory under `licenses/model/`) to `licenses/`, and `THIRD_PARTY_NOTICES.txt` with the name, version, licence and licence texts of every crate linked into the artifacts (with those of the C sources a crate builds, from the directories directly below it); upload them with the plugin. The manifest does not list them.

`alpha2-plugin-pack merge <pack-dir> <pack-dir>... --out <dir>` joins packs of the same plugin and commit made on several machines, each with the native artifact of its own target, into one directory: the first pack's manifest, wasm artifact (if it has one), resources and licences, with the native artifacts of the others added. Every pack must describe the same plugin (`id`, `version`, `abi`, `kind`, `descriptor` as written, `resources`, `about`) with the same licence files and notices, no two may have the same target, and every file must match what its manifest pins.

A plugin that runs a model the user already has declares a resource slot instead of pinning the model, and checks in `begin` that the files it got fit (`Context::supplied` lists them with their sizes): their names, the model's inputs and outputs, the vocabulary; it fails with a message naming what does not match. A native plugin whose runtime opens or maps the model itself asks `Host::resource_path` for every file the runtime opens, or for the directory that holds them, so the data records what was read; reading through `Host::resource` copies the bytes. A plugin that reads or hashes gigabytes does it in `begin` or as its input arrives, so that no call outruns the call deadline.
